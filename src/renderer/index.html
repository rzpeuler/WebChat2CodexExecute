    遇到基线阻塞时使用：先提交并同步工作区，再对齐最新基线；不会自动启动下一轮。
    
          
    
            维护动作流程与适用场景
            
    
              
    提交并同步 Git
    
              
    保留当前修改，创建提交并推送远端。适合确认修改属于当前项目且应保留时使用。
    
              
    对齐最新基线
    
              
    只刷新本地编排器记录的基线，不删除文件，也不会启动下一轮；工作区必须干净。
    
              
    放弃未提交修改
    
              
    仅人工触发。修改会先放入 Git stash，再清理工作区，适合确认这些修改不应继续保留时使用。
    
              
    结束本轮并等待新任务
    
              
    
                跳过当前已确认不再执行的输出，标记为已处理并进入等待 Sol 新输出；存在待同步代码或治理更新时不可用。
