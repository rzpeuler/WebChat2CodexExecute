# Sol 提示词预览长度与上下文分层设计

## 1. 目标

修复 Sol 初始化提示词超过 8000 字符后无法设置的问题，并确保“预览 Sol 提示词”展示的内容就是用户应复制到 Web Chat Project 背景中的初始化提示词。

本次只处理提示词预览和提示词编译边界，不改变自动循环、Writing Block 解析、治理一致性检查或当前 SHA 冲突处理。

## 2. 设计

### 2.1 初始化提示词

`initializationPrompt` 只包含：

- Sol、Luna、编排软件三者的职责边界；
- 默认执行语义和架构冻结边界；
- Writing Block 的稳定协议约束；
- 固定治理目录和模板路径；
- 当前项目必要绑定信息：项目 ID、本地路径、远端地址、目标分支、报告目录、治理 manifest 路径。

初始化提示词不再携带完整治理 manifest、治理文档索引、架构版本、Luna 报告摘要、治理缺口或任务书。这些内容属于易变化的回合上下文，不能放入需要长期保存的 Project 背景提示词。

初始化提示词设定硬上限 8000 个 JavaScript 字符。编译器在返回前校验长度；若稳定模板本身超过上限，抛出带中文诊断的错误，禁止生成一个看似可复制但实际无法设置的提示词。软件不对初始化提示词静默截断。

### 2.2 回合上下文

`dynamicContext` 继续承载完整项目快照和当前回合信息，供后续回合输入或诊断使用。其长度不受初始化提示词的 8000 字符限制，也不影响初始化提示词的可复制性。

### 2.3 预览反馈

预览接口返回初始化提示词的字符数和上限，前端在弹窗标题附近显示“字符数 / 上限”。正常情况下显示通过；若后端拒绝超限，沿用现有统一错误反馈，并不打开旧内容。

预览内容通过 `textContent` 展示并沿用现有一键复制能力，避免把提示词当作 HTML 执行。

## 3. 错误处理

- 模板目录或模板文件缺失、损坏：保持现有 fail-closed 行为；
- 初始化提示词超过上限：返回 `SOL_INITIALIZATION_PROMPT_TOO_LONG`，包含实际字符数和上限；
- 动态上下文较长：不影响预览成功，不截断其中的治理状态；
- 凭证脱敏：保持现有脱敏逻辑。

## 4. 验收标准

1. 初始化提示词在包含最长合理 Windows 路径、远端地址和模板路径时不超过 8000 字符。
2. 初始化提示词不再包含 `governance_active`、`governance_candidate`、`governance_history`、架构修订和 Luna 报告全文等回合数据。
3. `dynamicContext` 仍包含完整治理索引、架构修订和任务书回合数据。
4. 预览响应返回字符数与上限，前端可见展示并保持复制功能。
5. 超限测试、脱敏测试、模板校验测试和完整测试套件通过。
