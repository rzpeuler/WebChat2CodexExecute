# 自动循环统计、范围策略与阶段性目标汇报设计

## 目标

优化 Luna 代码同步的范围策略和 Dashboard 信息密度，同时增加项目级与连续运行级稳定性统计，以及一个不进入自动循环的阶段性目标汇报入口。

## 范围策略

- `IMPLEMENTATION` 任务：项目内非保护路径的修改允许同步；任务书 `scope` 作为预期范围而不是绝对硬边界。
- 超出预期范围的文件记录为 `scope_drift`，写入同步节点详情并通知 Sol，不重新执行 Luna。
- `TEST` 任务继续严格限制为 `tests/**` 和精确 `report_path`。
- 项目外路径、`.git/**`、治理文档、架构文档、凭据及任务 `out_of_scope` 保护路径继续硬阻塞。

## 执行统计

每个项目保存独立的自动化运行指标，不写入项目 Git：

- 连续运行会话的开始时间、结束时间、有效运行时长、已开始轮次、已完成轮次和结束原因；
- 项目累计有效运行时长、累计开始/完成轮次、连续运行次数；
- 等待 Sol 计入连续运行，暂停、阻塞和软件关闭期间不计入有效运行时长；
- 当前活跃会话在软件重启时以 `RESTARTED` 结束并持久化。

Dashboard 运行状态只显示项目、任务、当前基线、本次连续运行指标和项目累计指标；错误与动作反馈继续保留。

## Loop Graph 与计时器

- 前端不显示 `auto-repair` 节点。
- 自动修复仍保留后端持久化状态，但始终在 `parse-task` 节点详情中展示错误码、尝试次数、状态和等待信息。
- `run-luna` 节点根据节点 `startedAt` 实时显示本次 Luna 执行时长，并在完成、暂停或阻塞后冻结。

## 阶段性目标规划与任务梳理

维护与验收模块增加按钮“阶段性目标规划与任务梳理”。按钮只向已绑定的 Sol 会话发送独立提示词，不改变 Loop Graph、不启动 Luna、不解析 Writing Block。

Sol 检查四个维度：目标一致性、当前进度、方向偏移、风险与建议。输出必须是唯一的 `[USER_MESSAGE]...[/USER_MESSAGE]` 块，块内正文使用 Markdown；禁止 JSON/YAML 和包裹整个响应的 Markdown 代码围栏。

为避免消息与自动循环交错，该按钮只在自动循环未运行时可用，并具有忙碌状态与发送反馈。

## 验证

- Git 范围策略覆盖实现任务的非保护范围漂移、保护路径阻塞和测试任务严格范围；
- 运行会话在启动、暂停、阻塞、重启、恢复时统计正确；
- Dashboard 字段、轮次/时长计时器和自动修复详情渲染正确；
- 阶段性汇报命令发送正确、不会改变循环状态，并保持按钮状态管理。
