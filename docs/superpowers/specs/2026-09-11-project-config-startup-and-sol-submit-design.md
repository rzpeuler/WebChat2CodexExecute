# 项目配置启动回填与 Sol 提交确认设计

## 背景

当前项目配置存在两个互相关联的体验问题：

1. `projects.json` 按 `projectId` 覆盖，但 Git 扫描每次生成新的 `projectId`，导致同一个本地项目目录产生多条配置。
2. 主进程启动时会加载配置并尝试安装运行时，但渲染层没有加载配置并回填表单，导致后台已有配置而前端输入框为空。
3. Sol 的原始输入在 DOM 提交前写入会话绑定状态，且发送脚本只确认找到了输入框和提交控件，不能证明消息已经真正提交到 Edge。

## 目标

- 以规范化后的本地项目目录作为 `projects.json` 的唯一配置键。
- 保留同一目录现有 `projectId`，避免运行状态、会话绑定和 Codex 会话文件失联。
- 清理并兼容已有重复配置；启动时默认使用上一次保存/使用的项目。
- 启动时把配置可靠回填到前端，并在可能时刷新 Git 扫描信息。
- 只有确认 Sol 消息已经提交后，才记录 `lastRawInput`。
- 提交未确认时给出可诊断错误，不能静默进入等待状态。

## 非目标

- 不新增项目选择器或多项目管理页面。
- 不修改项目配置 schema，不增加独立的 active-project 状态文件。
- 不把 Edge 的会话绑定逻辑改成 Cookie 或账户密码登录。
- 不改变 Sol 单回合一个任务、治理一致性检查和 loop graph 的既有状态机语义。

## 设计

### 1. 项目配置的目录唯一化

在项目配置存储层增加本地目录唯一键：

- 使用 `resolve()` 规范化路径。
- Windows 比较时统一大小写和路径分隔符。
- 同一个目录的配置视为同一项目，即使输入的 `projectId` 不同。

保存时：

1. 先规范化输入配置。
2. 找到同目录的现有配置。
3. 如果存在，沿用现有配置的 `projectId`，以新配置内容覆盖旧配置。
4. 删除该目录的其他重复条目。
5. 将保存后的配置移动到数组首位。

加载时对历史数据做防御性归并：

- 同目录重复项保留原数组中最后出现的一条，兼容当前文件中后写入配置较新的情况。
- 归并结果移动到首位，并将清理后的列表持久化，避免重复项在下次重启再次出现。
- 其他不同目录的配置保持相对顺序。

列表首位即“上一次保存/使用的项目”。主进程继续使用首位配置安装启动运行时，因此不需要增加新的状态文件或 schema 字段。

### 2. 启动时配置回填

渲染层启动时调用 `loadProjectConfigs()`：

- 没有配置时保持现有空白初始化界面。
- 有配置时取列表首位，回填本地目录、远程仓库、目标分支和报告目录。
- 后端保存的报告目录是绝对路径，显示到输入框时转换为相对于项目根目录的路径；无法转换时保留绝对路径。
- 回填后重新执行一次 Git 扫描，刷新当前分支、HEAD、manifest 和模板状态。
- 刷新扫描只更新 Git 事实和项目详情，不覆盖已保存的目标分支与报告目录。
- 扫描失败时不清空已回填字段，并在状态栏显示“已加载配置但 Git 刷新失败”的中文反馈。

扫描结果用于后续保存和预览的事实校验；保存配置中的 `projectId` 由存储层按目录稳定复用，因此扫描生成的新临时 ID不会导致运行状态漂移。

### 3. Sol 消息提交确认

`CdpConversationController.sendMessage()` 在真实 DOM 操作后进行短轮询确认：

- 提交脚本必须找到输入框和提交方式；没有提交控件时立即返回失败。
- 提交后确认输入框已清空，或 Edge 状态已进入思考/出现新的助手消息。
- 在短超时内仍无法确认时抛出明确的提交确认错误，并包含“请检查专用 Edge 会话”的诊断建议。
- 不等待整轮 Sol 输出，输出等待仍由既有 orchestrator 负责。

`automation-runtime` 调整顺序为：

1. 校验绑定身份和运行许可。
2. 调用会话控制器完成并确认 DOM 提交。
3. 确认成功后写入 `lastRawInput`。

这样 `lastRawInput` 的语义变为“已确认提交到 Edge 的最近输入”，失败发送不会污染恢复状态。

## 错误与恢复

- `projects.json` 中存在重复目录：启动加载时自动归并并保存，不要求用户手工编辑。
- 已保存目录不存在或不再是 Git 仓库：输入框仍显示上次配置，状态栏提示重新选择/扫描；不自动覆盖配置。
- Sol 输入框不存在、提交控件不存在、提交后状态未变化：本轮立即失败并停在当前阶段，用户可检查 Edge 后重试。
- 提交确认失败时不得记录 `lastRawInput`，也不得进入“等待 Sol 回复”的状态。

## 测试边界

- 同目录、不同大小写/分隔符的配置保存后只有一条，且沿用旧 `projectId`。
- 历史重复配置加载后只保留最后一条并持久化清理结果。
- 不同目录配置互不覆盖，保存项目移动到列表首位。
- 渲染层启动回填全部字段；报告目录显示为项目相对路径；Git 扫描失败不清空字段。
- Sol 提交成功后才记录原始输入。
- 找不到提交控件、提交后输入仍存在、状态未变化时均返回失败且不记录原始输入。
- 既有项目配置、启动运行时和全部现有测试保持通过。

## 验收标准

1. 对同一个本地目录重复保存配置，`projects.json` 始终只有一条对应记录。
2. 重启软件后，前端默认显示上一次保存的项目及其配置字段，主进程也使用同一个项目启动运行时。
3. 在 Edge 实际没有提交 Sol 输入时，软件不会再报告“已发送”，不会写入 `lastRawInput`，并显示可操作错误。
4. 在 Edge 确认提交成功后，才进入既有的 Sol 回复等待流程。
