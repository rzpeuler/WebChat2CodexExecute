# Dashboard 状态与操作体验设计

## 目标

优化 Web Chat 2 Codex 的初始化和自动化 Dashboard，使用户能够按明确顺序操作，并能理解当前阶段、运行状态、异常原因和下一步动作。增加本地功能说明浮窗，不引入外部资源或新的登录机制。

## 界面结构

页面按用户操作顺序分为四个区域：

1. **项目准备**：选择本地目录、扫描项目、检查 Git 远程授权、克隆并初始化新项目、接管并初始化已有项目、保存配置、预览 Sol 提示词。
2. **连接 Web Chat**：打开专用 Edge、重新绑定 Sol 会话。
3. **自动循环**：启动、暂停、重试当前阶段。
4. **维护与验收**：治理一致性检查、打开项目目录、查看任务报告。

顶部显示项目名称、当前状态徽章、最近更新时间和“功能说明”入口。状态卡片保留项目、Sol 会话、阶段、任务、治理/架构版本、Luna、commit 和最近异常，并补充中文阶段/状态、错误原因和建议动作。

## 状态与操作模型

Dashboard 快照增加由后端计算的可用操作集合，前端不自行猜测复杂状态。每个操作包含 `enabled`、`busy` 和必要时的原因；前端据此禁用不适用按钮，并显示统一的处理中状态。

状态刷新间隔为 1.5 秒。命令提交后立即显示“已接受，后台处理中”，随后以快照为准更新结果。相同操作在进行中只能复用当前操作，不能创建第二个 Luna 任务或第二次 Git 同步。

“重试当前阶段”只允许用于可恢复的技术错误、外部配置完成后的阻塞和明确允许重试的推送恢复。Writing Block 协议错误、治理冲突、范围冲突、基线不一致和需要 Sol 重新规划的任务阻塞，不允许重复执行同一输出，界面应提示“请让 Sol 重新规划任务”。

阶段和状态使用稳定的中文映射，同时保留原始错误码。例如：

- `RUNNING_LUNA / RUNNING`：正在执行 Luna；
- `WAITING_FOR_SOL / RUNNING`：Luna 已完成，等待 Sol 验收或下一项任务；
- `PAUSED / NEEDS_USER_ACTION`：需要用户处理登录、外部账号、API Key、OTP 或 Git 授权；
- `FAILED`：执行失败，需要查看具体诊断；
- `PROTOCOL_ERROR` 或任务冲突：要求 Sol 重新输出/规划，不继续重试旧输出。

## 统一反馈

初始化按钮、Dashboard 按钮和预览操作均使用统一的异步操作包装器：开始时显示操作文案并锁定冲突按钮，成功时显示结果，失败时显示中文错误和建议，结束后恢复按钮。异常不得只写入控制台。

## 功能说明浮窗

增加“功能说明”按钮和本地模态浮窗，内容包括推荐操作顺序、状态含义、常见阻塞及处理方式、按钮可用条件。浮窗使用 `role="dialog"`、标题、关闭按钮、Esc 关闭、点击外部关闭和基本焦点管理。内容由本地 HTML 提供，不加载远程脚本、样式或图片。

## 验证

- Dashboard 快照契约测试覆盖可用操作字段和状态映射。
- Renderer 测试覆盖按钮忙碌/禁用、成功/失败反馈、周期刷新和浮窗键盘关闭。
- 类型检查、完整单元测试和构建必须通过。
- 验证重复点击不会重复发送启动、重试、重新绑定或治理检查命令。
- 不修改 Sol/Luna Writing Block 核心协议和 Git 提交策略。
