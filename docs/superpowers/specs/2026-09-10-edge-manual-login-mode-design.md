# Edge 人工登录模式设计

日期：2026-09-10
状态：已确认，第一阶段实施中

## 目标

为 ChatGPT 登录增加一个不依赖原始 Cookie 导入的人工登录模式，解决专用 Edge 以自动化标记启动后可能被登录服务拒绝的问题，并继续使用软件自己的 Edge profile 完成后续会话绑定。

## 范围

- 软件继续创建并持有独立的 Edge profile，不读取或复制用户日常 Edge 的 Cookie。
- Edge 以用户可见窗口启动，保留 CDP 远程调试和软件所有权校验。
- 移除 `--enable-automation` 启动参数，避免主动声明为自动化浏览器。
- Dashboard 仍使用“打开 Edge”和“重新绑定”完成启动与会话绑定，不嵌入 Edge 页面。
- 绑定仍校验账号、Project 和会话身份；绑定时最后一条历史消息仍只作为基线。

不在本阶段范围内：普通 Edge profile 的 Cookie 导入、浏览器扩展交接、任务 loop、治理文档、Luna 执行和按钮统一状态改造。

## 流程

1. 用户在 Dashboard 点击“打开 Edge”。
2. 软件启动或复用独立 profile，并打开 ChatGPT。
3. 用户在可见窗口中完成 Google、邮箱密码或其他可用的 ChatGPT 登录流程。
4. 软件通过页面状态识别登录是否完成；未登录时保持 `AUTH_REQUIRED`，不启动任务。
5. 用户打开目标 Project 和 Sol 对话，点击“重新绑定”。
6. 软件验证账号、Project、URL 和会话身份，保存会话及基线消息。
7. 用户点击“启动”，之后才进入首轮任务 loop。

## 安全边界

- 不导出、读取、复制或写入原始 Cookie、密码、验证码或令牌。
- 独立 profile 的数据仅由软件自己的 Edge 实例使用。
- 保留现有 CDP ownership token 和固定调试端口校验。
- 移除自动化标记不能保证登录服务一定放行；若仍失败，记录实际 URL、页面错误和网络环境，转入账号或服务侧诊断。

## 验收标准

- 启动窗口可见，且启动参数不包含 `--enable-automation`。
- 现有 Edge profile、项目配置和治理目录不受影响。
- 用户可以在该窗口完成一次人工登录，登录后的 profile 可在软件重启后复用。
- 登录未完成时不会允许会话绑定或启动任务。
- 登录完成后可以绑定目标 Sol 会话，且不执行绑定前的历史消息。
- 既有 Edge profile 单元测试、类型检查和构建通过。
- 若登录仍出现 Route Error，Dashboard 能显示明确的登录失败状态，而不是静默无响应。
