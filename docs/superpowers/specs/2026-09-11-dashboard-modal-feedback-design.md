# Dashboard 弹窗、布局与固定反馈设计

状态：已确认，待实现

日期：2026-09-11

## 1. 背景与目标

当前项目详情和 Sol 提示词会直接显示在页面底部，导致页面变长；自动循环图区域偏窄；执行反馈位于标题下方，页面滚动后不易观察。本次只调整前端展示，不改变后端协议、项目配置数据或自动化流程。

## 2. 设计

### 2.1 配置与提示词弹窗

- 项目详情使用“查看当前配置”按钮打开只读弹窗。
- Sol 提示词由现有“预览 Sol 提示词”动作生成后打开只读弹窗。
- 两个内容使用同一个通用弹窗容器，标题和内容按当前动作切换。
- 弹窗提供“一键复制”和“关闭”；支持点击遮罩关闭、ESC 关闭和焦点返回。
- 复制优先使用 Clipboard API；失败时保留内容并在状态条显示中文错误，不影响关闭弹窗。
- 页面不再显示原有两个大文本框，避免重复内容和纵向占用。

### 2.2 自动循环区域

- 工作台最大宽度从 `1120px` 调整到 `1360px`。
- 保持节点自身横向滚动和现有移动端断点，不改 Loop Graph 数据或状态模型。

### 2.3 固定执行反馈

- 将现有 `#status` 改为 `position: fixed` 的底部状态条。
- 状态条覆盖窗口底部并保留安全内边距，页面主体增加底部空间避免遮挡内容。
- 继续使用 `aria-live="polite"`，沿用现有成功、处理中、失败文本。

## 3. 交互与错误处理

- 打开弹窗前先完成现有异步生成动作；生成失败时不打开空弹窗。
- 弹窗内容始终按 `textContent` 写入，避免把配置或提示词解释为 HTML。
- 复制失败只提示，不自动重试、不阻塞其他操作。
- 弹窗状态独立于 Dashboard 状态刷新，后台轮询不应关闭或覆盖用户正在查看的内容。

## 4. 验证范围

- 验证配置弹窗、提示词弹窗的打开、关闭、ESC、遮罩关闭、焦点返回和复制成功/失败反馈。
- 验证自动循环区域在桌面端变宽，移动端仍可用。
- 验证底部反馈条在页面滚动前后保持固定，且不遮挡最后一段内容。
- 运行现有类型检查、构建和单元测试。

## 5. 非目标

- 不新增后端 IPC 接口。
- 不改变配置保存、提示词编译、自动循环、状态机或 Git 行为。
- 不引入复杂的多标签弹窗、可编辑配置或新的通知系统。
