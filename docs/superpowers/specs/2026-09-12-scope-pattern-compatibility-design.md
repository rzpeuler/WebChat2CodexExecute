# 目录范围模式兼容设计

## 背景

Luna 任务书中的 `scope` 可能使用 `knowledge/production/` 表示递归目录，当前 Git 匹配器只把 `/**` 识别为递归目录，导致合法工作区变更在 `sync-code` 阶段被误报为 `UNAUTHORIZED_CHANGE`。

## 目标

- 新任务书统一生成 `/**` 形式的目录范围。
- Git 安全匹配器继续兼容历史任务书中的目录末尾 `/` 形式。
- 当前已持久化的 `pendingCodeSync` 可以直接重试，不重新执行 Luna。
- 单文件路径仍然精确匹配，不能因为兼容目录写法而扩大范围。
- 保护路径、工作区基线和未授权变更检查保持不变。

## 方案

在 Git 路径模式匹配的统一入口中，将末尾 `/` 解释为递归目录；`/**` 保持现有递归语义，`/*` 保持单层目录语义，其他模式保持精确匹配。任务书模板和提示词使用 `/**` 作为规范写法。

当前状态中的 `allowedPaths` 不需要手工迁移，因为重试时匹配器会兼容旧值。

## 验证

- 验证 `directory/` 和 `directory/**` 都能匹配目录下任意文件。
- 验证目录模式不会匹配无关目录。
- 验证单文件路径仍只匹配自身。
- 验证当前 `RHL-M3B-1-FIX-001-GATEWAY-CORRECTNESS-001` 的 pending sync 可以在不重跑 Luna 的情况下继续。
