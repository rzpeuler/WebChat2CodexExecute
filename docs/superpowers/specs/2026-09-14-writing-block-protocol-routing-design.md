# Writing Block 协议候选识别与 Sol 输出路由设计

## 目标

让 W2C 从完整的 Sol assistant 消息中稳定找到可消费的机器协议，同时允许思考和普通说明文字存在，不再把这些文字误判为协议错误。Sol 负责判断输出面向 ORCHESTRATOR 还是 USER；W2C 只执行协议，不推断普通文本的语义。

## 输出路由

- ORCHESTRATOR：输出一个或多个合法 Writing Block。W2C 提取并执行，不要求消息其他位置为空。
- USER：输出一个 `USER_MESSAGE` block。W2C 停止自动循环、保存状态并发出 Windows 通知。
- 只有普通文本：W2C 没有可执行信号，进入 `SOL_OUTPUT_UNCONSUMABLE`，暂停并通知用户；Sol 提示词要求避免这种输出。

## 候选识别

解析器扫描完整 assistant 文本，使用 `[WRITING_BLOCK type="..."]` 作为候选起点，但不再使用“从消息开头到结尾必须全部是块”的规则。JSON 候选先通过字符串、转义符、对象和数组层级扫描确定完整正文，再要求结束标记闭合；随后读取顶层字段名，检查模板字段顺序和重复字段，最后交给既有 JSON 与业务校验器。

候选失败时继续检查后续候选。前置的残缺候选可被后置完整候选替代；合法候选之后出现新的残缺候选时保留错误，避免静默丢失最新输出。多个合法 `LUNA_TASK` 仍然报重复任务；多个架构冻结块仍然允许。

## 模板与提示词同步

内置模板、治理标准文档和 Sol 提示词均由 W2C 源码生成。Dashboard 的“升级治理协议与 Sol 提示词”入口负责将当前内置治理树覆盖式升级到已托管项目，先备份旧托管文件，再重新生成 Sol 提示词预览。该动作不会自动修改 ChatGPT Project 背景，需要用户复制预览内容完成背景更新。

## 边界

- Writing Block 内仍必须满足 JSON、字段类型、枚举值、保留标记和业务规则。
- 普通文本不能替代机器协议，也不会被 W2C 当作可执行指令。
- 无法由 W2C 执行且需要用户决定的事项必须使用 `USER_MESSAGE`，不能依靠普通说明文字传递。
