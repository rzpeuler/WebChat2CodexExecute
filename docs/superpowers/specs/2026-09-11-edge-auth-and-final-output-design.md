# Edge 登录验证与 Sol 最终输出识别设计

## 目标

修复两个相互独立但都会阻塞自动循环的问题：

1. Sol 开始思考时，专用 Edge 页面中的隐藏登录元素被误判为 `AUTH_REQUIRED`。
2. ChatGPT assistant DOM 的完整 `innerText` 将思考区、状态区或隐藏辅助文本并入最终输出，导致合法可见的 Writing Block 被解析为块外存在非空文本。

## 约束

- 不修改 Writing Block 严格协议：整条交给解析器的最终回答仍必须只包含合法 Block。
- 不增加“块前多余文本/块后多余文本”的错误码细分。
- 不自动截取任意一段文本执行，避免误执行隐藏或第二条指令。
- 实际登录墙、上下文过长、网络错误和会话丢失仍然必须暂停并通知用户。

## 设计

### 1. 页面快照与登录判定

页面内脚本使用可见性判断，而不是仅判断登录相关节点是否存在。登录墙仅由以下信号触发：

- 可见的明确登录/已退出节点；
- ChatGPT 登录或认证路径；
- 可见的成对登录表单字段；
- 适配器显式返回的登录标记。

隐藏的 `input[type="email"]`、登录模板节点以及普通状态文本不得单独触发认证错误。适配器不再用 `loginSelectors` 的正则去匹配拼接后的状态文本。

### 2. 最终回答提取

保留最后一个可见 assistant 消息作为消息边界，但在该消息内部：

- 优先寻找可见、同时包含 Writing Block 开始和结束标记的最深层内容节点；
- 找到时只返回该内容节点的可见文本；
- 找不到完整标记时返回最后 assistant 消息的可见文本，让现有协议解析器继续报告未闭合或格式错误；
- 不改变块内 JSON/YAML 校验和重复任务校验。

这样可以排除同一 assistant DOM 中的思考面板和辅助状态文本，同时不把真正的块外说明静默吞掉。

运行时诊断还确认 ChatGPT DOM 当前可能返回 XML 形状的等价外壳：`<WRITING_BLOCK type="TYPE">...</WRITING_BLOCK>`。Edge/协议边界只对这一种完整、精确的外壳做规范化，内部统一转换为标准方括号协议；不会放宽正文、字段或块外文本校验。提示词同时明确要求 Sol 生成标准方括号外壳。

### 3. 测试

- DOM 快照脚本只将可见登录墙判定为认证需要。
- 隐藏登录表单不触发 `AUTH_REQUIRED`。
- 含思考文本和最终 Writing Block 的 assistant DOM 只提取最终 Block。
- 没有完整 Block 时仍保留现有严格解析行为。
- 现有全量类型检查、构建和测试必须通过。
